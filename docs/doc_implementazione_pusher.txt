Di seguito la versione operativa.

Ruoli stanza

admin: creatore sessione (scrivania_sessioni.creatore_id)
editor: può move/rotate/scale/flip, non può spawn
viewer: read-only
Permessi derivati (client)

canRead: admin/editor/viewer
canWrite: admin/editor
canSpawn: solo admin
canManageMembers: solo admin
Identificatori

session_token: stringa in URL /tool-scrivania/?token=... (sempre token sessione)
session_id: bigint interno DB, usato nei canali Pusher
invite_token: solo landing invito, consumato al termine del flusso
REST API V1 (namespace scrivania/v1)

Resolve session + snapshot iniziale
POST /wp-json/scrivania/v1/get-session
Input: { token: session_token }
Output:
{ session_id, session_token, role, permissions, state_version, snapshot }
Permessi: logged-in + (creatore OR membro invitato claimato; fallback email solo per inviti legacy non claimati)
Implementazione:
Plugin: remote_inner/plugins/scrivania-collaborativa-api/includes/class-scrivania-api.php (estende get_session_data)
Fetch snapshot (refetch)
GET /wp-json/scrivania/v1/session/{session_id}/snapshot
Output: { session_id, state_version, snapshot, updated_at }
Permessi: canRead
Implementazione: plugin (nuova route nello stesso file)
Save snapshot (end gesture)
POST /wp-json/scrivania/v1/session/{session_id}/snapshot
Input: { base_version, snapshot, reason }
Output: { session_id, state_version }
Permessi: canWrite (editor+admin)
Concorrenza: se base_version !== current_version → 409 { current_version }
Side-effect: trigger Pusher state-updated
Implementazione: plugin (affianca o sostituisce logica di save_session_data)
Spawn carta (admin-only)
POST /wp-json/scrivania/v1/session/{session_id}/spawn
Input: { base_version, card_template_id, initial }
Output: { session_id, state_version, spawned_card_id }
Permessi: canSpawn (solo admin)
Side-effect: persiste snapshot e trigger state-updated
Implementazione: plugin
Claim invito (consume)
POST /wp-json/scrivania/v1/invites/claim
Input: { invite_token }
Output: { session_id, session_token, role, permissions }
Permessi: logged-in + email utente = email invitata (prima del bind) + invito non revocato + (verifica email completata)
Side-effect: set invitato_user_id, claimed_at, consumed_at, e rende il token inutilizzabile
Implementazione: plugin (tema chiama questo endpoint da landing invito)
Landing: remote_inner/themes/hello-theme-child-master/page-invito-scrivania.php
Gestione membri (admin-only)
PATCH /wp-json/scrivania/v1/session/{session_id}/members/{user_id}
Input: { role: viewer|editor } oppure { action: remove }
Output: { success, member }
Permessi: canManageMembers (solo admin)
Side-effect (opzionale): Pusher member-role-updated / member-removed
Implementazione: plugin
Pusher V1 (presence)

Canale: presence-scrivania-{session_id}

Auth endpoint: POST /wp-json/scrivania/v1/pusher/auth

Auth permessi: logged-in + canRead sulla sessione estratta dal channel_name

Presence user:

user_id: WP user ID
user_info: { display_name, avatar_url } (email opzionale)
Eventi:

state-updated: { session_id, state_version, updated_by? }
Client: coalescing 100–300ms, se state_version > localVersion → refetch snapshot
(Opzionale) member-role-updated, member-removed
Implementazione:

Plugin: remote_inner/plugins/scrivania-collaborativa-api/includes/class-scrivania-api.php (rafforza authenticate_pusher_channel)
Snapshot JSON (schema V1)

snapshot:
cards: array di
{ id, template_id, x, y, z, rotation, scale, flipped, meta? }
viewport: { panX, panY, zoom } (solo se vuoi viewport condivisa; altrimenti locale)
Non includere nello snapshot: selezioni temporanee, dragging in corso, cursori live.
Regole client (React)

Autosave: solo su end-gesture (drag end, rotate end, scale end, flip click) + debounce 300–800ms.

Realtime: ascolta state-updated e refetcha snapshot (coalesced).

Gating UI:

admin: spawn abilitato
editor: drag/rotate/scale/flip
viewer: tutto disabilitato
