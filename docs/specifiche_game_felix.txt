📄 Specifiche implementazione inviti WordPress per gioco Unity WebGL single-user

🎯 Obiettivo
Permettere a un utente pagante sulla piattaforma WordPress di:
- selezionare un gioco Unity disponibile in dashboard;
- invitare un solo contatto per sessione;
- generare un link valido 24 ore;
- permettere l'accesso solo all'utente invitato;
- caricare il build corretto del gioco tramite il campo ACF unity_build_url.

🧩 Componenti principali
- Dashboard utente: page-dashboard-utente.php
- Creazione invito: innerplay-inviti-manager.php, action AJAX attiva_gioco
- Gate ingresso invito: page-gioca.php
- Pagina finale del gioco: single-gioco.php
- API REST residue per Unity: /wp-json/game/v1/user-profile

📦 Struttura dati (DB)
Tabella: wp_game_sessions
- id
- host_user_id
- gioco_id
- invito_uuid
- invited_email
- invited_user_id
- claimed_at
- first_access_at
- status
- created_at
- expires_at

Tabella legacy riusata: wp_giochi_invitati
- mantenuta per compatibilità storica e tracciamento minimo
- non è più la fonte autorevole dei permessi della sessione

🔗 Link invito
Ogni sessione genera un link del tipo:

https://miosito.it/gioca?invito=56fb1d23-aa22-4ed3-910b-8c29ab763111

Accesso consentito solo all'utente invitato, con login WordPress obbligatorio.

⚙️ Flusso d’uso
🟢 Creazione sessione
- L'utente abilitato apre la dashboard.
- Sceglie un gioco disponibile.
- Seleziona un solo contatto dalla rubrica.
- Clicca Invia invito.

WordPress:
- valida il post di tipo gioco;
- valida una sola email destinataria;
- crea una riga in wp_game_sessions con invito_uuid univoco e expires_at = now + 24h;
- salva invited_email e, se esiste già un utente WordPress con quella email, invited_user_id;
- invia una email con link /gioca?invito={invito_uuid}.

🟡 Apertura link invito
- L'utente invitato apre /gioca?invito=...;
- se non è loggato, viene reindirizzato al login WordPress con redirect di ritorno;
- WordPress verifica che la sessione esista e non sia scaduta;
- WordPress verifica che l'utente loggato coincida con invited_user_id oppure con invited_email;
- se invited_user_id è ancora vuoto ma l'email coincide, il sistema esegue il bind dell'utente alla sessione;
- infine l'utente viene reindirizzato al permalink del gioco con invito_uuid.

🔵 Apertura gioco
In single-gioco.php WordPress:
- ricarica la sessione tramite invito_uuid;
- verifica di nuovo esistenza, scadenza e autorizzazione;
- usa titolo_gioco e descrizione_gioco dal post gioco associato alla sessione;
- usa unity_build_url del post gioco associato alla sessione per valorizzare l'iframe Unity.

🔄 API REST (WordPress → Unity)
Endpoint attivo:
GET /wp-json/game/v1/user-profile
- Input: invito_uuid
- Autenticazione: utente loggato e autorizzato sulla sessione
- Output:
  {
    "status": "ok",
    "user": {
      "id": 123,
      "username": "nomeutente",
      "display_name": "Nome Utente",
      "email": "utente@example.com"
    },
    "session": {
      "id": 10,
      "gioco_id": 55,
      "invito_uuid": "uuid-sessione",
      "expires_at": "2026-05-14 10:30:00"
    }
  }
- Errori possibili: 401 auth_required, 403 forbidden, 404 session_not_found, 410 expired

Endpoint rimossi dal flusso giochi:
- GET /wp-json/game/v1/get-join-code
- POST /wp-json/game/v1/set-join-code

🔐 Sicurezza
- Login obbligatorio.
- Gating applicato sia su /gioca sia sul singolo gioco.
- Il link non abilita l'accesso a utenti diversi dall'invitato previsto.
- Dopo il primo accesso riuscito, la sessione può essere vincolata all'utente WordPress specifico tramite invited_user_id.

⏳ Scadenza inviti/sessioni
- expires_at viene impostato alla creazione della sessione a +24h.
- page-gioca.php, single-gioco.php e l'endpoint user-profile rifiutano accesso se la sessione è scaduta.
- Non esiste più estensione automatica della scadenza tramite join code.

🎛️ Limiti
- Una sessione gioco corrisponde a un solo invitato.
- L'host crea l'invito ma non è più considerato partecipante della sessione di gioco.

📌 Note implementative
- La dashboard mostra il titolo del gioco usando prima ACF titolo_gioco e, se vuoto, il titolo standard del post.
- single-gioco.php mostra un errore esplicito se unity_build_url non è configurato.
- wp_giochi_invitati resta presente per compatibilità con dati e binding pregressi, ma la sessione vive in wp_game_sessions.
